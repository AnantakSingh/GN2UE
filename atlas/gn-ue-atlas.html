How translation actually works

There is no node-for-node converter and never will be — Blender and Unreal split the same jobs across different engines. Every Geometry Nodes graph decomposes into lanes, and each lane has one right UE home:

Scatter & instancingpoints, instances, distribution → PCG. The strongest lane — samplers, Transform Points, Static Mesh Spawner. Proven by SpineTree.
Curves & splinescurve primitives, sampling, travel → PCG + Splines. Spline Sampler covers most reads; primitives are exported as analytic points.
Mesh editingbooleans, extrude, subdivide, UVs → Geometry Script — or the bridge's cheat code: bake to FBX at export and skip the lane entirely.
Time & simulationScene Time, Simulation Zones → Niagara. PCG has no frame feedback; animated effects are a per-family Niagara translation.
No lanevolume grids, Grease Pencil, hair, closures UE has no counterpart system. Conservative skip — flag clearly, never fake it.
  • Randomness is statistical, never per-element. Blender and UE RNGs can't be matched; a translated effect has the same look and distribution, not identical placements. (Locked in with SpineTree.)
  • Only the point domain crosses over. PCG has points with attributes; Blender's vertex/edge/face/corner fields have no UE home — mesh-field graphs must bake or go to Geometry Script.
  • PCG is not time-driven. One graph, regenerated on demand. Anything that evolves per frame belongs to Niagara.
  • Graph parameters need C++. UE 5.8 exposes no scripting API to declare PCG parameters — the strongest argument for the client plugin being a real C++ plugin.

Suggested bridge tiers

Tiers weigh how often a node appears in real effect graphs against implementation cost. Filter the atlas by tier below to see exactly which nodes each one commits to.

V1 · core

The scatter + curve backbone: exactly the nodes the SpineTree and curve-travel families already exercise, plus the math/attribute glue they imply. High frequency, low complexity, all PCG.

V1.x · next

Widens the same families: object/actor binding, texture-driven density, trims and offsets, loops, Accumulate Field via one HLSL kernel. Each unlocks visibly richer effects without a new architecture.

Later

Real but lower-frequency work: Geometry Script mesh ops, curve-to-mesh sweeps, Niagara simulation families. Each is its own project; schedule by demand.

Bake / skip

Either the FBX bake at export already covers it (mesh primitives, SubD, shading), or UE has no counterpart (volume grids, Grease Pencil, hair, closures). The exporter flags these, never guesses.
